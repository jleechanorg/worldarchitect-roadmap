# Pilot audit — intent classifier (Pass A zero-code, then Pass B strict ZFC)

Source: pilot subagent report, 2026-10-28. Read-only; nothing written or committed.
Scope: `mvp_site/intent_classifier.py` (1,886 lines) and
`mvp_site/intent_classifier_warmup.py` (183 lines) in `jleechanorg/worldarchitect.ai`.

Verdicts are exactly KEEP, ADAPT, or DELETE. Final verdict is the stricter of
the two passes, unless a named product promise rescues it (named explicitly).
Nothing in either file earns KEEP: nothing here is transport, durable writes,
tool execution, authorization, or bounded capacity, and no registered exception
names the classifier. The in-repo registry covers backend *adjustments* (e.g.
XP-threshold recomputation), not intent classification.

ADAPT here means work items at the call sites, not code retained in these
files. Both files are deleted in full; ADAPT means the *guard role* survives in
changed form elsewhere, while the similarity implementation is deleted.

## Why the modal-exit promise does not rescue the scorers

The named product promise in play is the CC Exit Guarantee (design doc
2026-05-11: "user must always explicitly exit," trust anchor the modal lock;
level-up follows the same pattern). It rescues the *guard* (the modal lock and
conclude policy, which live in `agents.py`/`modal_conclude_policy.py`, outside
this audit), not the scorer: the doc's Layer 1 (CHOICE prefix / JSON payload)
is already an explicit signal, and the scorer (Layer 2) was added for
convenience with avowedly "narrow scope, low false-positive risk" — i.e. it
*accepts* false positives, which is the opposite of explicit consent.

## Blast radius of deleting the classifier (output-shape dependencies)

- **What consumes the output shape.** `predict` returns `(mode: str, confidence: float)`, consumed by `agents.py`'s routing state (`intent_mode`, `confidence`), its semantic dispatch table (mode → agent, including the `MODE_CHARACTER` → StoryModeAgent default), its metadata (`classifier_source`, `confidence`), and the CC-completion check that compares confidence against a threshold. The exit predictors return `(bool, float)`, consumed by `agents.py`'s conclude-signal helper and modal conclude paths and by `modal_conclude_policy.detect_conclude_signal`, which takes the classify functions as injected parameters. Deleting the classifier therefore requires rewiring exactly three consumption points: the semantic routing step (replace with model self-routing, or a `mode` field on the structured response validated server-side — mode values themselves stay, since the dispatch table is keyed on them), the CC-completion gameplay-intent check, and the modal conclude paths (rewired to explicit signals per the two ADAPT items).
- **What degrades gracefully, and what does not.** The existing degraded mode already proves the shape of naive deletion: every classifier failure today falls back to `MODE_CHARACTER` → StoryModeAgent, and a rewards fallback refuses to let a degraded classifier skip the mechanical rewards lane. So deleting without rewiring reproduces degraded mode permanently: every turn gets StoryModeAgent's largest prompt set, and typed-text modal exits stop working (Layer-1 explicit signals keep working). The ADAPT rewiring exists precisely to avoid silently landing in that degraded mode.
- **Boot and process wiring.** `main.py` imports both modules, waits on classifier readiness in its lazy-warmup path, and dispatches background warmup at startup; `mcp_api.py` calls `initialize()` in its server path; the `ENABLE_SEMANTIC_ROUTING` flag becomes meaningless. All of that is deleted with the classifier, not adapted.
- **What survives outside these files (not verdicts here, but the boundary).** The modal lock and conclude policy (`agents.py`, `modal_conclude_policy.py`), the commit execution that finalizes state, dice execution/audit (the standing "keep anti-cheat" decision — server tool execution, allowed under Pass B), and server logging (the standing "keep server logging" decision — observability, not a domain decision). Neither standing decision rescues anything in these two files, because neither is implemented here.
- **Tests (flag, not audited).** `test_intent_classifier.py`, `test_conclude_signal_detection.py`, routing/dispatch tests, `test_firebase_mock_mode.py`, and reward-routing tests reference these symbols and will need rework or deletion alongside the code.
- **The file header docstring** (the ~180-line routing contract at the top of `intent_classifier.py`) is a design statement, not a symbol, but it goes with the file: it asserts the routing design that both passes reject.

## Bottom line per file

- **`intent_classifier.py`: DELETE in full, with two ADAPT work items at the call sites.** No method earns KEEP: nothing here is transport, durable writes, tool execution, authorization, or bounded capacity, and no registered exception names the classifier. The two exit predictors are ADAPT only in the sense that the modal conclude guard must be rewired to explicit signals (CHOICE/JSON payload or explicit player confirmation) — their similarity implementations, thresholds, and anchors are deleted, not retained.
- **`intent_classifier_warmup.py`: DELETE in full.** Both warm paths serve a deleted model; one is already dead in production, and the other exists only to hide load latency that no longer exists.
