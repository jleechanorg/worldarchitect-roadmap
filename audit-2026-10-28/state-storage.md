# State-storage audit — second run (local copy, no GitHub API)

**Source:** `~/workspace/repos/worldarchitect.ai/mvp_site/` (main-branch ZIP tree, no
`.git` history). Read-only: no repo file was changed, no deletion, no PR.
**Method:** Pass A zero-code baseline (bare conversation log + Gemini API) then
Pass B strict ZFC (model owns all campaign-domain facts; server provides ONLY
transport, durable writes, tool execution, authorization, bounded capacity).
Final verdict = stricter pass, unless a named product promise rescues it
(named explicitly). A field-aware transform fails unless it names a specific
registered exception AND proves that exception necessary; registry membership
alone proves nothing, and determinism, schema validity, display formatting, or
normalization alone never justify one. Caller data below is a token scan over
`mvp_site/*.py` plus `mvp_site/tests/test_*.py` (first 6 external files shown);
a private helper with no external file is normally an internal caller, not
proof of zero use — internal use was checked by reading the file, and
genuinely unreferenced symbols are called out as such. This supersedes the
prior BLOCKED run in this file: that run issued no verdicts because GitHub MCP
returned 429; this run read the local tree instead, so the 429 blocker is moot
and no GitHub call was made.

**Jeffrey's §6 standing decisions (override everything else):** (1) server
logging KEEP, ADAPT to async/batched where it blocks a turn; (2) anti-cheat
KEEP, dice resolution stays on the turn path, only the audit trail may go
async; (3) faction/living-world KEEP but ADAPT to async background ticks
merged on the next turn, never blocking the turn path. **Conflicts found:
none.** Living-world stamping/pruning verdicts below are ADAPT-to-async
